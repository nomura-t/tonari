# となり（声で回す学び）

自分の PC だけで使う学びのアプリです。話題を何本も並べ、話題Aで声で質問したら答えを待たずに話題Bへ移り、答えが届いた話題に戻って読みます。答えは文字と図で返り、説明の中心の概念を、上に上位概念、下に下位概念、左右に対の概念、斜めに関係する概念を置いた図で見せます。理解度は概念ごとの申告と、関係ごとの確かめで持ちます。答えを開く前に予想を一言話す帯と、時間をおいて戻ったときに出る確かめの問いがあります（v0.3）。設計は `DESIGN-となり-声で回す概念の学び-2026-10.md`、調べた材料は `research/` にあります。文書の中の「本人」は、このアプリを使う人のことです。

Mac で作って毎日使っています。Windows では、下の「Windows で使う」の文を Claude Code に貼ると、clone から起動までを Claude Code が進めます。

## 要るもの

Claude Code（`claude` コマンド）が入っていて、ログインして動くこと。先生役（答えを書く役）と整形役（文字起こしを直す役）は、`claude -p` をあなたのログインのまま子プロセスで動かします。Claude の API キーは使わず、使った分はあなたの Claude のプランの枠から減ります。先生役の既定は opus で、使えないプランなら `TONARI_TUTOR_MODEL=sonnet` で変えます。設定の画面では fable・opus・sonnet から選べます。

ほかに `uv`（Python の実行）と `ffmpeg`（録音の変換）が要ります。声を文字にするのは、Mac では Apple の聞き取り（端末内・無料）、Apple の無い PC では speech.cpp で動かす Haas-ja-v1.0（端末内・無料・日本語向け）です。ElevenLabs の鍵を入れると Scribe も使えます（そのときは録音が ElevenLabs に送られます）。

## Mac で使う

Xcode のコマンドラインツール（swiftc）も要ります。`bash app/build_app.sh` でアプリ「となり」（`~/Applications/となり.app`）を作り、開きます。Spotlight で「となり」と打つか、Finder でホームの中の「アプリケーション」を開きます（サイドバーの「アプリケーション」は Mac 全体の /Applications なので、そこには無い）。アプリはサーバーを自分で起動し、閉じるとサーバーも止めます（`run.sh` で先に起動していればそれを使い、閉じても止めない）。最初に話すとき、macOS がマイクの使用を1回だけ確かめます。

アプリはビルドした時点の uv・claude・ffmpeg の場所を覚えているので、入れ直して場所が変わったら作り直します。作り直したら、開いているアプリを一度終了して開き直します。アプリを使わずにブラウザで開くなら `./run.sh`（Chrome で `http://127.0.0.1:4880/`）。窓を出さずに起動から停止までを確かめるのは `~/Applications/となり.app/Contents/MacOS/Tonari --selftest --port 4882 --snapshot /tmp/t.png`（`--js '<式>'` で画面を操作してから撮れる）。サーバーのログは `~/Library/Logs/tonari/server.log`。

## Windows で使う

Claude Code を入れてログインしたあと、好きなフォルダで PowerShell を開いて `claude` を打ち、次の文を貼って送ります。Claude Code が clone から、入れるものの確認、`setup.ps1`、試験、起動までを進めます。

Claude Code に貼る文:

```text
声で学ぶアプリ「となり」をこの PC で使えるようにしてください。
1. https://github.com/nomura-t/tonari を、ホームの下の tonari フォルダ（%USERPROFILE%\tonari）に git clone してください。
2. そのフォルダの SETUP-windows.md を読み、その手順どおりに進めてください。何かを入れる前に、入れるもの・入れる場所・かかりそうな時間を私に見せて、確かめてから入れてください。
3. 最後に、私がふだんどう起動すればよいかと、確かめた結果を短く教えてください。つまずいて直したことがあれば、そのフォルダの CLAUDE.md の末尾に書いておいてください。
```

手でやるなら、`git clone https://github.com/nomura-t/tonari.git` のあと、そのフォルダの PowerShell で `powershell -ExecutionPolicy Bypass -File .\setup.ps1` を流します。入るのは uv・ffmpeg・speech.cpp と Python の部品で、最後に準備の表が出て、スタートメニューとデスクトップに「となり」ができます。開くと Edge のアプリ窓になり、窓を閉じると15秒後に裏のサーバーも止まります。中身は `SETUP-windows.md`、起動役は `launch.py`、用意の仕上げは `prepare.py` です。

## 設定の画面

左の列の下の「設定を開く」で開きます。この PC の準備（Claude Code・ffmpeg・聞き取りの道具・Scribe の鍵が使えるか、使えないときの直し方）、キーの割り当て、聞き取りの方式、ElevenLabs の鍵、先生役のモデル（fable・opus・sonnet から選ぶ。新しい話題から使う）、読み方（送ったら移る・読む前の予想の出し方・答えの字の大きさ・届いた知らせの音・聞かずに Web で調べる）を、ここで見て変えます。キーは「変える」を押してから使いたいキーを押すと変わり、変えていない操作は OS の既定（Mac は ⌘、ほかは Alt）のままです。同じキーを2つの操作に割り当てようとすると断ります。準備が足りないときは、左の列と最初の画面に1行で知らせます。

## 操作

| キー | すること |
|---|---|
| ⌘N（Windows は Alt+N） | 新しい話題を作り、そのまま録音を始める |
| Space | 録音を始める・もう一度押すと送る（文字の欄にいるときは効かない）。先生役への発言になる。別の話題から戻って答えが畳まれているあいだだけは、予想になる |
| Esc | 録音をやめる（送らない） |
| ⌘]（Windows は Alt+]） | 答えの届いた話題へ移る（古い順）。届いていなければ待っている話題へ |
| ⌘1〜⌘9（Windows は Alt+1〜9） | 左の列の順で話題を開く |
| ⌘M（Windows は Alt+M） | 全体の地図を開く・閉じる（地図の中では、Esc が探す字・選んだ物・地図の順に閉じる） |
| ⌘Enter（Windows は Ctrl+Enter・文字の欄） | 打った文を送る。Enter だけなら改行（日本語入力の確定の Enter で送らないため） |
| Enter | 畳んである答えをすぐ読む。入力欄の上の帯が出ているときは、帯の声のボタン（待つあいだの予想・確かめへの答え）を押すのと同じ。どちらでもなければ、いちばん新しい答えの「続きを」 |

表のキーは既定の割り当てで、設定の画面で変えられる。送ったあと答えの届いた話題へ自動で移るかは、設定の画面の「送ったら答えの届いた話題へ移る」で切り替える。聞き取りの方式も同じ画面で、「精度優先（毎回 Scribe）」「自動（口座の残りが 5,000 を切ったら Apple だけ）」「端末だけ（Apple）」から選ぶ。

読む前の予想と、戻ったときの確かめは、入力欄のすぐ上の帯に出る（v0.6・DESIGN 17章）。同じ話題で答えを待っているあいだは、帯が「答えを待つあいだに、予想を一言どうぞ（任意）」と誘う。帯の欄に打って送るか、帯の「声で予想」（Enter）で話すと、予想は先生役に送られずに、届いた答えの上に残る。何もしなければ、答えはそのまま開く。別の話題にいるあいだに届いた答えは、戻ったときに畳んであり、このあいだは Space も文字の欄も予想になる（Enter ですぐ読める）。出し方は、設定の画面の「答えを読む前の予想」で選べる。予想をすると、予想のすぐ下に結果の1行（答えの核心が予想に入っていたか）が出て、答えの本文の終わりに「予想と答えの照らし合わせ」が出る。答えの核心（先生役の答えの最初の文）が予想に入っていたかと、合っていた所・予想に無かった決め手・食い違っていた所・答えが触れていない所を、予想と答えの字のまま返す（点数や段は付けず、理解の記録にも入れない）。「なぜ違ったかを聞く」を押すと、予想を添えて先生役に聞き返す。確かめの問いは答えの下には出ず、答えを開いてから2分以上たってその話題に戻ったときに、1つだけ帯に出る。帯の欄に打って送るか、帯の「声で言う」（Enter）で話すと先生役が判定し、二度目の判定役と一致した当たり・半分だけが理解の記録に入る。Space と文字の欄は、帯が出ていても先生役への発言のままである。帯の「ヒントをもらう」を押すと、先生役が問いごとに書いたヒント（考える方向・もう一歩の2段まで。想定の答えの字を含む段は機械で外す）が1段ずつ出て、出した段の数が記録に残る。当たりで記録されたときは、判定の行に「読んでから○日あけて、何も見ずに言えた」と事実だけが出る。「確認ですけど〜ですよね」と自分の言葉で言い直したときも判定する（DESIGN 13章・15.5・17章）。

答えの図は中身に合わせて先生役が選ぶ（分岐の木・時間軸・流れ・しくみの絵・比較の表・重なりの図・計算の例・たとえ・階層の木・関係の図・位置の図、一言で足りるなら文だけ）。しくみの絵は、部品の箱（入れ子は1段）と番号つきの受け渡しの矢印で、置き場所は画面が決め、図の下の一覧の行か番号を指すと、その矢印と両端の箱が光る（DESIGN 15.4 の B2）。図の上に表現の名前と、その形にした理由が出る。答えの下の「短く」「別の見せ方で」「詳しく」で同じ中身を言い直してもらえる（「別の見せ方で」は前の図と新しい図を横に並べる）。上の帯の「自動・短く・詳しく」は話題ごとの答えの長さで、自動は確かめの問いに答えられた概念ほど短くする。

本人の発言の下線は整形役が直した箇所で、押すと聞き取りどおりの字に戻した文で聞き直す画面になる。点線は決めきれなかった箇所（候補は字に重ねると出る）。「直して聞き直す」で書き換えた字は聞き違いの台帳に入り、次から聞き取りの手がかりになる。

図の札を押すと右の地図がその概念を中心に描き直し、2回押すとその概念の説明を頼む。右の地図では、概念の申告（分かる・あやしい・分からない）と、関係ごとの確かめ（✓・?）を付けられる。右の列の「全部」は、話題ごとの言葉の一覧で、片づけた話題も入り、話題の名前を押すとその話題を開く。右の列の上の「全体の地図」（⌘M）は、話題を島として並べ、話題に出てきた言葉と関係の全部を1枚で見渡す画面で、同じ言葉が別の話題にも出てくるときは島と島を線で結ぶ。引くと島の名前と説明を受けた言葉だけになり、寄ると全部の言葉が読める。言葉か島を押すと右に中身（関係の文・その話題の言葉の一覧）が出て、そこから話題を開く・位置の図へ進む・説明を頼むことができる。島の置き場所は開くたびに同じで、並べ直すのは「島を並べ直す」を押したときだけである。

## 記録の置き場

Mac は `~/Library/Application Support/tonari/`、Windows は `%LOCALAPPDATA%\tonari\`（SQLite の `tonari.db`、本人の録音 `audio/`、棚の本文の写し `corpus/`、整形役の作業場所 `work/`）。リポジトリには入れない。先生役の会話は Claude Code の記録（`~/.claude/projects/` の下、作業フォルダ `corpus/` の分）に残り、`--resume` で続きから始まる。ただし `--resume` は会話を始めたときの指示を使い続けるので、先生役の指示（`server/tutor.py` の SYSTEM）が変わったあとの話題は、次の往復で新しい会話を始め、その話題のこれまでの往復（最近の8つ・図の塊を除いた本文）を添える（DESIGN 15.11）。

## 守っていること

Claude の API キーは使わない。先生役（opus）と整形役（sonnet）は、手を加えていない `claude -p` を本人のログインのまま子プロセスで動かし、子の環境から `ANTHROPIC_*` を外す。先生役は `--restricted --tools Read,Grep,Glob` で棚の写しだけを読む（棚は作者の手元の道具で、無ければ資料なしで答える）。サーバーは 127.0.0.1 だけで待ち受け、`/api` は独自の見出し `X-Tonari: 1` が無いと断る。Scribe を使うときは録音が ElevenLabs に送られる。

## 設定（環境変数）

環境変数のほか、記録の置き場の `.env` に `TONARI_…=値` の行で書いてもよい（環境変数があればそちらが勝つ。`prepare.py` はここに書く）。

| 変数 | 既定 | 中身 |
|---|---|---|
| `TONARI_DATA_DIR` | Mac `~/Library/Application Support/tonari`・Windows `%LOCALAPPDATA%\tonari` | 記録の置き場（試験のときは別の場所にする） |
| `TONARI_PORT` | 4880 | 待ち受けの番号 |
| `TONARI_TUTOR_MODEL` / `_EFFORT` | opus / （既定） | 先生役 |
| `TONARI_TUTOR_MAX_ALIVE` / `_IDLE_SEC` | 6 / 1800 | 常駐させる先生役の上限と、閉じるまでの秒数 |
| `TONARI_FIXER_MODEL` / `_EFFORT` | sonnet / low | 整形役 |
| `TONARI_SCRIBE` | auto | Scribe の既定（画面で変えた値が優先） |
| `TONARI_ELEVEN_MIN_REMAINING` | 5000 | 自動のとき、口座の残りがこれを切ったら Scribe を使わない |
| `TONARI_RETURN_AFTER_SEC` | 120 | 答えを開いてからこれだけたって話題に戻ったら、その答えの確かめの問いを1つ出す（DESIGN 13.2） |
| `TONARI_LOCAL_ASR` | auto | Scribe を使わない回に speech.cpp の Haas-ja-v1.0 を使うか。auto は Apple の無い PC でだけ使い、`haas` は Mac でも Apple と並べて2本目にし、`off` は使わない（測った結果は DESIGN 3.1.1） |
| `TONARI_SPEECH_BIN` | （空） | speech.cpp の `speech` の場所。空なら PATH と `~/.local/bin/speech`（.exe も）と Windows の `%LOCALAPPDATA%\Programs\speech.cpp\current\speech.exe` を探す |
| `TONARI_FFMPEG_DIR` | （空） | ffmpeg と ffprobe のあるフォルダ。空なら PATH と Windows の winget の置き場を探す |
| `TONARI_EXIT_WHEN_CLOSED` | （空） | `1` で、画面が閉じられて15秒たったらサーバーが止まる（`launch.py` が立てる） |
| `TONARI_STT_BIN` | `stt/bin/stt-helper` | Apple の聞き取りの道具（Mac だけ） |
| `ELEVENLABS_API_KEY` | （空） | Scribe の鍵。環境変数に無ければ、記録の置き場の `.env` の `ELEVENLABS_API_KEY=` の行を読む |
| `TONARI_CLAUDE` | （空） | `claude` の場所。空なら PATH を探す（Windows は `claude.exe` を先に） |
| `TONARI_KEEP_ANTHROPIC_ENV` | （空） | `1` にすると子の環境から `ANTHROPIC_*` を外さない（claude を API キーなどで動かしている PC 向け） |
| `TONARI_SHELF_LIB` | `.claude/.artifacts` | 棚の写しの場所（作者の手元の道具。無ければ資料なしで動く） |
| `TONARI_PREDICT_FEEDBACK` / `_MODEL` | on / （記録役と同じ） | 読む前の予想と届いた答えを照らし合わせて返す照らし合わせ役（`off` で止める。記録役を止めているときは動かない。DESIGN 17.12） |
| `TONARI_READINGS` / `_MODEL` | on / （記録役と同じ） | 話題の最初の問いに別の読みがあったかを、答えのあとに確かめる読みの判定役（`off` で止める。記録役を止めているときは動かない。DESIGN 17.6） |

## 検査

規則の検査は `uv run --group dev pytest`（直しすぎ・判定の根拠・札の読み取り・対の向き・聞き違いの拾い方・「」の照合・図の塊ごとの決まり・しくみの絵の部品とやりとり・ヒントの決まり）。文字起こしの方式ごとの誤り率は `uv run python -m tests.stt_eval`（Apple だけ）、`--scribe`（Scribe の用語あり・なし）、`--fixer`（Apple＋整形役）、`--haas`（Haas の用語あり・なし）、`--fixer --haas [--no-glossary]`（Apple と Haas の2本を整形役に）。整形役は回ごとに揺れるので、比べるときは3回以上回す。たとえと実物の結びつき・図の形・答えまでの秒（DESIGN 15.7・15.9）は `uv run python -m tests.eval_grounding --n 3 --out <置き場>/x.json` で測る（本物の先生役に作り物の12問を新しい話題として流す。記録の置き場は起動のたびに新しい一時フォルダで、同時に動かすのは3本まで。Max の枠を使う）。並べた表は `--report a.json b.json`、数える役だけのやり直しは `--rejudge x.json`。v0.4 作業B からは、しくみの絵を狙う作り物の2問（14問）と、確かめの問いのヒントの数（付いた割合・機械が外した段）も数える。本人の記録の数（使った日数・往復・確かめに答えた率・ヒントの段数・「実際には？」の回数・たとえの塊が出た往復）は `uv run python tests/usage_stats.py`（数だけを出し、話題の名前や発言は出さない。記録の置き場を SQLite の読み取り専用で開く。`--db <path>` で別の記録、`--json` で JSON）。画面の流れは `uv run python tests/ui_flow.py`（Mac だけ。アプリの実行ファイルが要る）で確かめる。作り物の先生役（`tests/fake_claude.py`）でサーバーを立て、アプリの検算の窓（窓を出さない）で `tests/ui/` の場面を流す。Claude の枠は使わず、記録の置き場は流すたびに作る一時のフォルダである。名前の一部を渡すとその場面だけを流し、`--shot <png>` で終わりの画面を撮る。作り物の先生役は、`TONARI_CLAUDE=<tests/fake_claude.py の場所>` でサーバーを起動すれば、手で画面を触るときにも使える（`TONARI_FAKE_DELAY` が答え始めるまでの秒）。読みの判定役の測りは `uv run python tests/eval_alt.py`（作り物の17組を本物の判定役に流す。Max の枠を使う）。予想の照らし合わせ役の測りは `uv run python -m tests.eval_predfb --n 2`（作り物の19組を本物の照らし合わせ役に流す。Max の枠を使う）。試しの音声は `tests/audio/`（正解の文と用語の一覧）。合成音声6本は macOS の声の使用許諾で再配布できないのでリポジトリに入れておらず、Mac では `bash tests/audio/make_mac.sh` で作る。ほかの PC では `texts.txt` を読み上げて録った wav を「名前-行の番号.wav」で置く。`spike/` は 2026-10-29 に方式を決めたときの試し（opus 3本の同時起動、Apple の2方式の文脈の語と別候補）。

## v0.5 で足したこと（2026-11-13・設計は DESIGN 16章）

答えは、ふつうは 250字ほどの短い答えで返り、答えの下の「続きを」（いちばん新しい答えでは Enter）で続きが出る。詳しくと言えば長く、一言でと言えば短くなる。字数の目安と理由は答えの下に小さく出る。記録用の地図と確かめの問いは、答えが届いたあとに記録役（`server/recorder.py`・`TONARI_RECORDER=off` で止める・モデルは `TONARI_RECORDER_MODEL`）が作る。

先生役の推測・仮定・考えの筋道は、破線の枠の「考えの塊」で事実と分けて出る。「あなたはどう思う？」「推測でいいので」と聞くと自由に書く。

位置の図は、線ごとに「中心 は 相手 つなぐ言葉」の文として読める形になった（上＝広い言葉、下＝種類、横＝取り違えやすい相手、箱の中＝部品）。

手元の資料に無く、確かでないことは、答えの下の「Web で調べてページにする」で調べられる（`server/research.py`）。調べ役が Web を調べ、サーバーが出どころのページを取りに行って引用の字を照らし、照合役が引用が主張を支えているかを判定する。ページは記録の置き場の `pages/` に残り、次からは先生役の根拠になる。問いの文が検索に送られるので、既定では押したときだけ走る（設定の「聞かずに Web で調べる」で自動にできる）。調べ役のモデルは `TONARI_RESEARCH_MODEL`（空なら話題の先生役と同じ）。

間合い・記録役・考えの塊の測りは `uv run python -m tests.eval_tempo --n 2 --out <置き場>/tempo.json`（本物の先生役に作り物の18問を流す。Max の枠を使う）。

## v0.6 で変えたこと（2026-11-15・設計は DESIGN 17章）

主な経路（問う→読む）を止めていた所を直した。先生役の指示は変えていないので、いまある話題の会話はそのまま続く。

読む前の予想は、場面で出し方が分かれる。同じ話題で答えを待っているあいだは、答えを畳まず、入力欄の上の帯で任意に誘う。予想を言い始めていれば、届いた答えは送るかやめるまで畳んでおく。別の話題にいるあいだに届いた答えは、戻ったときに畳んであり、このあいだは話すキーも文字の欄も予想になる。誘うのは問いの形の発言だけで、誘った往復を予想なしで開いたら、次の1回は誘わない。文字で書いた予想には「質問として送り直す」が付く（予想の欄に質問を打ってしまったとき用）。

戻ったときの確かめの問いは、往復の列の上でなく、入力欄の上の帯に出る。確かめに答えずに先生役へ発言を送ると帯は下がり、問いは残って、次に戻ったときにまた出る。「あとで」は、問いを残したまま帯を下げる。アプリを起動したときに1回だけ、ほかの話題（片づけた話題を含む）にいま出せる確かめの問いがあれば、「1問だけ思い出してみる」と帯で誘う。

話題の最初の問いに別の読みがあったときは、答えの下に「別の読みでしたか」の札が出る（答えのあとに、読みの判定役が裏で確かめる）。札を押すと、その読みで聞き直す。

片づけた話題は、左の列の下の「片づけた話題」に並び、押すと一覧に戻って開く。右の列の「全部」は、話題ごとの言葉の一覧になった（例と非例の文は並べない）。送った問いは往復の列の上に来て、答えの頭がすぐ下に見える（自分で列を動かすまで、その位置を保つ）。答えの字は 17px になり、設定の「答えの字の大きさ」で3段から選べる。届いた知らせの音は設定で止められる。新しい話題を作って録音が始まったあと、文字を打ち始めると録音はやめる。

同じ日の本人の指摘と依頼で、2つ足した。読む前の予想には、答えとの照らし合わせが返る（DESIGN 17.12）。答えが届いたあと、先生役とは別の照らし合わせ役が、先生役の答えの最初の文（答えの核心）が予想に入っていたかを判断し、答えの本文の終わりに返す。出す字は予想と答えの字のままで、点数も段も付けず、理解の記録にも入れない。この版より前にした予想にも、押せば照らし合わせを付けられる。

話題と言葉の全体を1枚で見渡す「全体の地図」を足した（DESIGN 17.13）。右の列の上の「全体の地図」か ⌘M で開く。最初の画面にはせず、押したときにだけ開く。
